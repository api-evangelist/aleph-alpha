# Aleph Alpha

> Aleph Alpha is a Heidelberg, Germany based sovereign AI company building PhariaAI, an end-to-end,
> customizable AI suite for enterprises and governments, deployable on-premise or hosted. PhariaAI is
> exposed through six documented HTTP APIs and first-party Python, Rust and JavaScript tooling.
> Generated by API Evangelist (apis.io) on 2026-08-02 from Aleph Alpha's published documentation and
> OpenAPI definitions. Aleph Alpha does not publish an llms.txt of its own (probed 2026-08-02, 404).

## APIs

- [PhariaInference API](https://docs.aleph-alpha.com/phariaai-dev-guide/latest/pharia-openapi/pharia-inference/index.html): Completion, chat completions, embeddings, semantic and instructable embeddings, evaluate, explain, tokenize/detokenize, transcribe, translate, rerank, steering concepts, model listing, API token management. Hosted at https://api.aleph-alpha.com. Current version 4.7.0.
- [Responses API (Stateful Responses)](https://docs.aleph-alpha.com/phariaai-dev-guide/latest/responses-api/index.html): OpenAI-Responses-compatible stateful API with conversation persistence, SSE streaming, guardrails, client-executed function tools and server-executed MCP tools.
- [PhariaSearch / Document Index API](https://docs.aleph-alpha.com/phariaai-dev-guide/latest/pharia-openapi/pharia-search.html): Semantic search over a knowledge base — namespaces, collections, documents, indexes, filter indexes, chunk inspection.
- [PhariaData API](https://docs.aleph-alpha.com/phariaai-dev-guide/latest/pharia-openapi/pharia-data.html): Repositories, datasets, datapoints, stages, files, connectors, transformations and transformation runs, search stores.
- [PhariaStudio API](https://docs.aleph-alpha.com/phariaai-dev-guide/latest/pharia-openapi/pharia-studio.html): Projects, OTLP traces, spans, events, evaluation datasets, benchmarks, benchmark executions, lineages, workspaces.
- [PhariaOS Manager API](https://docs.aleph-alpha.com/phariaai-dev-guide/latest/pharia-openapi/pharia-os.html): Cluster GPUs and nodes, use cases, deployments, foundation models, inference runtimes, model registration. Swagger 2.0.

## Notes for agents

- Authentication is `Authorization: Bearer <token>` on every call. The hosted gateway returns
  `401 No client token provided` for every path except `GET /version`.
- There is no idempotency key. Retrying a failed `POST /complete`, `POST /chat/completions` or
  `POST /v1/responses` may duplicate work. The PhariaSearch and PhariaData write surfaces use
  caller-named `PUT`s instead, which are naturally idempotent.
- No rate-limit headers are published. Backpressure arrives as `503` with a queue-full message.
- Errors use `{"error": {"message", "type", "param", "code"}}`, not RFC 9457 problem+json.
- No public status page, no A2A agent card, and no `/.well-known/` documents are served.
